# ADR-0003: 레이트 리미팅 — 인메모리 고정 윈도우, 전 라우트 기본 적용

- 상태: 채택 (2026-08) · 후속 과제 있음
- 관련 코드: `lib/rate-limit.ts`, `lib/server/api-handler.ts`

## 컨텍스트

공개 API는 남용(스크래핑, AI 비용 폭탄, 알림 스팸 등록)에 노출된다. 특히
`/api/compare`는 호출당 LLM 비용이 발생한다. 반면 이 서비스는 Vercel 무료
티어 기반이라 Redis 같은 공유 스토어 도입은 비용·복잡도 트레이드오프가 있다.

## 결정

1. 고정 윈도우 카운터를 프로세스 메모리(Map)에 유지한다 (기존 구현 유지).
2. 파이프라인의 `rateLimit` 옵션으로 **모든 공개 라우트에 기본 적용**한다.
   비용/민감도에 비례해 수치를 차등화한다:
   - compare 20/분 (LLM 비용) · share-guest 10/분 (DB 쓰기+스팸)
   - watches/push 30/분 · price/history/track 60/분
3. 표준 헤더를 반환한다: 429에 `Retry-After`, 성공에 `X-RateLimit-Remaining`
   / `X-RateLimit-Reset` — 클라이언트가 백오프를 구현할 수 있게 한다.
4. 키는 `prefix:클라이언트IP` (`x-forwarded-for` 첫 값).

## 알려진 한계 (의도적 수용)

- 서버리스 인스턴스별 상태 → 콜드 스타트에 리셋되고 인스턴스 수만큼 상한이
  곱해진다. **1차 방어선**이지 정확한 쿼터가 아니다.
- IP 기반이라 NAT 뒤 사용자들이 버킷을 공유한다.

## 후속

트래픽이 유의미해지면 Upstash Redis(슬라이딩 윈도우) 또는 Supabase 기반
카운터로 교체한다. 파이프라인 뒤에 숨어 있으므로 교체 시 라우트 수정은 없다.
